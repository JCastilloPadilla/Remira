# Análisis con evidencia y OCR local — plan

> Ejecución autorizada por el usuario: implementar todas las mejoras propuestas. Usar pruebas antes de implementación y dominios paralelos con archivos separados.

**Goal:** leer mensajes con texto e imágenes, separar spam de phishing y presentar señales, incertidumbre y cobertura verificables.

**Architecture:** extracción puntual en extensión, OCR Tesseract local empaquetado sin llamadas externas, API loopback con análisis de enlaces sin visitarlos, clasificación por idioma como señal auxiliar y tres resultados explicables. Importación opcional de .eml aporta cabeceras declaradas, nunca una verificación criptográfica.

**Tech Stack:** React/TypeScript, Tesseract.js, Flask, modelos locales existentes, pytest/Vitest/Playwright.

## Restricciones

- Preservar cambios previos de frontend/API/CORS y pruebas; copia de referencia en tmp/analysis-v2-baseline.
- Sin OAuth, descarga automática de imágenes del correo, navegación a enlaces ni envío de correos a servicios externos.
- Capturar por acción explícita solo regiones visibles de imágenes del mensaje elegido. Si cambió pestaña/mensaje/geometría, releer; imágenes fuera de vista quedan pendientes.
- OCR local en español/inglés; assets empaquetados. Fallos, baja confianza o imágenes sin revisar implican cobertura incompleta.
- No deducir autenticidad del remitente visible. Cabeceras importadas se identifican como declaraciones no verificadas.
- No cambiar 'spam' por 'malicious'. La puntuación del modelo no es probabilidad calibrada de seguridad.
- Mantener modelos históricos y sus evaluaciones; no presentar datos sintéticos como medición en correos reales.
- Rama actual; sin push automático y sin confirmar cambios previos ajenos.

## Contrato compartido

Entrada POST /api/analyze:
`{subject:string, body:string, sender?:string, links?:{text:string,url:string}[], coverage?:{images_total:number,images_pending:number,ocr_low_confidence?:boolean,links_complete?:boolean}, authentication?:{source:string,spf?:string,dkim?:string,dmarc?:string}}`.

Respuesta mantiene `label`, `confidence`, `max_tokens`, `model`, `language`, `task` (valores del modelo seleccionado; `label=unavailable` y `confidence=null` si no disponible). Añade:
`assessment: {verdict:'suspicious'|'no_clear_signals'|'inconclusive', reasons:{code:string,severity:'info'|'warning'|'danger',message:string}[], limitations:string[], text:{language:string,token_count:number,processed_tokens:number,truncated:boolean}, coverage:{images_total:number,images_pending:number,ocr_low_confidence:boolean,links_complete:boolean}, links:{url:string,host:string,decoded_url?:string,issues:string[]}[], authentication:{source:string,spf?:string,dkim?:string,dmarc?:string,verified:boolean}}`.

Modelos: español Tanaos spam/not_spam, inglés Cybersectony legitimate/malicious. Nunca una opinión del modelo basta para afirmar phishing. Falta de cobertura/idioma/modelo o una opinión negativa sin evidencia suficiente => inconcluyente. No claro no equivale a seguro.

GET /api/health identifica tarea híbrida, modelos y readiness. POST /api/analyze-eml acepta multipart file con tope explícito y devuelve respuesta más `email:{subject,body,sender,links,coverage,authentication}`. No abrir adjuntos ni guardar el original.

## Verificación y riesgos

Probar factura transaccional sin excepciones por marca; remitente falsificado; enlaces con destino discrepante/redirectores; idiomas no soportados; texto largo; correo solo imagen; OCR fallido/parcial; modelo ausente; edición/relectura; preservar CORS local y rechazo de webs remotas; no solicitudes de red externas durante análisis.

- Carga de modelo fallida/idioma no soportado/cobertura incompleta: resultado no concluyente. SPF/DKIM/DMARC importados siempre declarados, no verificados.
- Cambios previos preservados; sin push ni commit automático. API y servidores locales quedan disponibles para pruebas manuales. No se abrió una cuenta Gmail real desde la automatización.
